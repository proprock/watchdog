# WD-195 Hook Facts Implementation Plan

**Goal:** Import Watchdog event facts into Insights, expose session hook metrics,
and report token differences without changing either accounting convention.

**Architecture:** Extend read contract v1 with paged, read-only event and fact
iterators ordered by the source events rowid. Import their appended records
under machine/project identity with one shared incremental cursor. Keep derived
hook data separate from transcript projections. Metrics read those projections;
doctor reports main/subagent reconciliation and unknown values explicitly.

**Tech Stack:** Python 3.14, SQLite, pytest, existing readapi and wdi CLI.

## Scope and decisions

- Acceptance: contract tests, incremental/idempotent import, session permission
  wait and tool durations, delivered action/rule counts, four token dimensions
  split between main and subagents, doctor output, and a live reconciliation
  table with follow-up IDs for discovered discrepancies.
- No provider calls, token-accounting fixes, UI redesign, dependencies, or
  changes to raw stored records. WD-186 and WD-197 remain open for their stated
  timing/provider limitations.
- Prefer the existing import orchestration and SQLite schema to another store
  or a second importer command. Contract columns are documented before code.
- Both readers yield dictionaries including `event_rowid`; `after_rowid=0`
  starts at the beginning, each page closes its read transaction before yield.
  Facts use the parent events rowid, not the projection's internal rowid.
- `hook_events` retains events fields for permission/control evidence;
  `hook_facts` retains all FACT_COLUMNS. Keys include machine and project IDs.
  Cursor key: `wd-facts://<machine_id>/<project_id>`.
- Main usage has no agent_id; subagent usage has an agent_id. Reconcile against
  main/non-main transcript messages, retaining NULL as unavailable. A difference
  exceeds 1% when abs(wdi-watchdog) > abs(watchdog)*0.01 (zero versus nonzero
  differs); do not silently normalize provider accounting conventions.
- Permission waits start at observed permission prompts and end only on
  matching resumed tool/turn evidence; incomplete waits remain unavailable.
  Count only control actions with delivery evidence, not recommendations.
- The append cursor does not detect later model/effort attribution backfills;
  `--full` rebuilds those projections. WD-220 tracks an incremental refresh
  signal for existing facts. Token fields used here are not modified by that
  attribution backfill.

## Steps

1. Document events and FACT_COLUMNS in docs/read-contract.md. Add provider-free
   tests for readers, import, metrics, reconciliation, and CLI diagnostics.
2. Run focused tests and commit the failing tests alone with WD-195 and TDD:red.
3. Implement readers in src/agent_watchdog/readapi.py. Implement derived schema
   and importer in insights/src/wdi/ingest/hook_facts.py; invoke it from the
   existing Watchdog import. No package upgrade code; add a one-off script for
   the installed Insights database if a conversion is needed.
4. Implement insights/src/wdi/metrics/hooks.py and doctor/session CLI output.
5. Run focused root and Insights tests, then root/Insights suites, Ruff, ty,
   package builds and diff hygiene once on the stable diff. Review the result.
6. Run read-only live reconciliation using the imported facts. Record totals,
   discrepancies and new follow-up IDs in docs/evidence/wd195.md. Close WD-195
   only after all acceptance checks pass. Commit the implementation TDD:green
   and audit the red/green pair. No push or live daemon changes.
