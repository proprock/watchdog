# WD-200 Comparison Implementation Plan

**Goal:** Compare two independently filtered selections of sessions without model calls.

**Architecture:** A shared comparison module validates JSON filters, resolves observed session metrics and manual labels, and calculates numerical statistics and categorical outcome distributions. The CLI and web page consume the same result. Unknown values remain separate from zero.

**Tech stack:** Python, SQLite, Typer, FastAPI, Jinja, pytest.

1. Add failing tests for filter validation, numerical statistics, missing observations, labels, and session selection; implement the shared module.
2. Add the CLI and page with tests for normal, empty and invalid inputs.
3. Document filter syntax and metric semantics; run focused tests, both applicable suites, static checks, and inspect the final diff. Record evidence and close WD-200 only after all acceptance criteria pass.

Selections use JSON objects with `project`, `provider`, `model`, `since`, `until`, `label`, and `session_ids` keys. All supplied fields intersect. Dates are ISO dates; the ending date is inclusive. The 90th percentile uses nearest rank. Outcome labels are categorical, so they show counts rather than numerical statistics. HEAD movement is represented as 0 or 1. Missing or incomplete observations remain unknown.
