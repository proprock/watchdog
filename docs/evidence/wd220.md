# WD-220 verification

## Failure and decision

Late Codex context repairs model and effort on existing source usage facts.
The source event rowid does not change, so the append-only Insights import
cursor misses that repair. Token reconciliation does not depend on these
attribution fields.

Incremental import now pairs its append cursor with a bounded historical
refresh. Each store refreshes at most 500 old facts per import. The separate
`wd-facts-refresh://<machine>/<project>` import-state record stores progress
in `byte_offset` and the fixed cycle high-water mark in `file_size`; these are
logical rowids rather than file offsets. Finishing a cycle resets both to zero;
the next call starts a new cycle at the previous append cursor. Initial and
full imports seed a cycle at the imported high-water mark.

Freezing the boundary prevents new appends from extending an active cycle.
Large stores need multiple incremental imports before every backfill is
visible; a full import remains the immediate-refresh option. Historical refresh
updates only model, effort, and their provenance, including null values.
Raw imported envelopes and token columns remain unchanged. Refresh updates,
new events, and both cursor changes share the per-store import transaction.
No schema revision or installed-store conversion is needed.
