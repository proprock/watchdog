# WD-165: Codex model, effort and subagent attribution

Date: 2026-10-18. Branch: `feature/wd-165-codex-attribution`.

## Observation contract

Codex turn-context configuration is retained as bounded, versioned metadata,
without creating synthetic turn-start events or retaining context instructions.
The reader's attribution cursor upgrades prior tool-reader cursors once. Usage
response identities, counters and WD-131 child-rollout deduplication remain
unchanged. Attribution and execution grammars have separate version gates.

The derived usage projection resolves model and effort within the same provider,
session, child identity and explicit turn at the native response time. Without
an explicit turn, it uses the latest earlier context. A missing context field
stays unavailable; a conflicting field at the same native time stays unknown.
Requested spawn overrides do not establish the child's resolved configuration.
Missing native launch/response timestamps cannot substitute later ingestion time.
Late context updates derived facts, without rewriting usage envelopes or receipts.
Reader windows defer those repairs per agent; durable markers survive interruption
and are removed atomically with successful repair. A narrow projection marker
repairs older derived Codex configuration once. Legacy migration and ordinary
inheritance also isolate colliding provider/session identities.

Local read-only inspection of the installed `0.163.0-alpha.10.2` rollout confirmed
`turn_context.payload.model`, flat `effort` and `turn_id`. This qualifies only
configuration observation. Its execution/control grammar remains separately
unqualified; tool-enrichment gaps are retained. No provider invocation was used
to inspect those field shapes.

Subagent reporting separates requested overrides, the coordinator's configuration
at launch, and the child's observed configuration. Native identity links spawn
results and later message, wait and close operations; opaque code bodies cannot
supply identities or results. Missing identity, transcripts, usage and final
results remain visible coverage gaps. Closing an agent is not task success.
Unknown usage is not zero, and unpriced tokens are disclosed. No billed-spend
claim or automatic model rewrite is introduced.

Report windows bound displayed child observations while coordinator lookups can
use earlier configuration evidence. The digest reuses one raw/normalized event
snapshot and one usage projection for its common window; raw tool namespace
validation does not issue a second event query. The initial full-suite run
exposed that extra query, and the shared-cache correction is covered by
`test_digest_uses_one_snapshot_and_parses_each_loaded_envelope_once`.
