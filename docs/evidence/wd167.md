# WD-167: frozen Codex calibration cohort

Date: 2026-10-20. Status: **prepared; human review and coverage acceptance pending**.

## Frozen evidence

The existing `scripts/calibrate.py sample` pipeline selected 40 Codex sessions
from a read-only SQLite backup of the watchdog project's retained history.
The observation window is 2026-09-07 00:00 UTC through 2026-10-20 00:00 UTC,
inclusive by event receipt time. The sample was frozen at
2026-10-20 19:03:38 UTC, before requesting any WD-167 verdicts.

- [Sample](wd167-sample.json): exact frozen session IDs, findings, fingerprints,
  evidence IDs, receipt boundaries and selection parameters.
- [Freeze manifest](wd167-freeze.json): sample/database SHA-256, repository
  revision, evaluated source hashes and execution/attribution projection scope.
- [Coverage](wd167-coverage.json): per-session version/surface availability,
  outcome provenance, behavior categories and supporting event IDs.
- [Review record](wd167-review.json): stable F01-F32 finding and S01-S28 silent
  session identifiers. Null verdicts and timestamps mean pending human review.
- [Calibration](wd167-calibration.json): current human-reviewed denominators.
  Seven findings have fresh human verdicts; 25 remain pending.

The local backup, source copies, review cards with captured inputs/results and
extraction scripts remain under ignored `tests/local/wd167/`. The original
backup is retained unchanged; live history may later be pruned or enriched.
Its hash in the manifest identifies the exact local evidence used. Raw
transcripts, machine-local configuration and project mappings are not exported.

The sample SHA-256 references identify the original frozen local bytes, which
use CRLF line endings. Git stores the same JSON with LF line endings under the
repository policy; `repository_sample_sha256` in the freeze manifest identifies
that representation. Replacing LF with CRLF in the repository sample reproduces
the original sample hash without changing any finding or selection. Historical
WD-146 sample hashes likewise refer to the original local bytes.

without findings, for a target of 40. Thirty Codex sessions below the event
minimum were excluded; 70 Claude sessions were excluded by provider. This is
one project's retained history, not a representative provider benchmark.

Polling/waiting inventory uses explicit waiting events and tool operations.
It is a coverage inventory, not a proposed exclusion in `repeated_tool_outcome`.
Shell status checks and opaque code-mode polling also appear in the review
cards; JavaScript text does not establish a native execution identity or effect.

Execution outcome attribution is available for 3,917 normalized finish/waiting
observations: 367 success, 59 failure and 3,491 unknown. The provenance is 331
structured exit-code records, 95 structured patch-status records, 393 opaque
code-mode frames and 3,098 missing results. Success is not task progress; unknown
results cannot be interpreted as successful or failed commands.

All 13,950 raw events have unavailable surface attribution. Provider version is
unavailable for 12,508 events; explicit versions are `0.162.0-alpha.17.2`
(1,371), `0.163.0-alpha.10.2` (67) and `0.162.0-alpha.2` (4). A session can span
versions; per-session counts are in the coverage record, and finding evidence
version availability is in the review record. No version or CLI/desktop surface
is inferred from the currently installed application. Observation gaps include
unsupported tool versions, invalid rollout lines, native session mismatch and
unreadable transcripts. Their event references are retained in coverage.

`gpt-6-luna` (9), `gpt-6-sol` (2), `gpt-6.1-sol` (50); high effort (42) and medium

No sampled finding or fingerprint was rewritten to correct the extraction.

## Reproduction and remaining acceptance

With the installed instance's exact CONFIG/DATA/RUNTIME arguments from its hook,
the existing sampling command is:

```text
uv run python scripts/calibrate.py sample --config CONFIG --data DATA --runtime RUNTIME \
  --project watchdog --provider codex --since 2026-09-07T00:00:00+00:00 \
  --until 2026-10-20T00:00:00+00:00 --min-events 20 --settle-hours 2 \
  --target 40 --seed 167 --output SAMPLE
```

The recorded run used `--home tests/local/wd167/home` against the backup instead
of live instance arguments. Rerunning against later live history is a new
measurement. The frozen sample, database and source hashes govern this one.
`scripts/calibrate.py report --sample SAMPLE` joins recorded annotations without
recomputing findings; `--rule-version` would intentionally create a different
evaluation and must not silently replace this freeze.

The local pipeline baseline report includes historical labels and project-wide,
mixed-provider delivery timing. Those fields are not fresh WD-167 false-negative
or Codex latency measurements. The published calibration record instead uses
the existing `rule_precision` calculation with an empty fresh-review denominator.

Remaining work is to record the user's TP/FP/uncertain verdicts for the other 25 findings and
fresh progress/task-outcome reviews for S01-S28, then calculate precision as
TP / (TP + FP). Uncertain and unreviewed cases enter neither that denominator
nor a promotion minimum. Slow/stuck no-finding sessions are false-negative
candidates; the count is currently unavailable, not zero. Keep every review
bound to provider, body/version and fingerprint, with its actual review time.

Background execution, interruptions and explicit surface attribution still need
qualified observations. WD-165 model/subagent coverage cannot qualify a requested
model override as an observed child configuration. WD-167 remains open until
the human reviews and coverage gaps are resolved or explicitly accepted as
unavailable with their consequences recorded. WD-147 and WD-159 may consume
only this disclosed scope; unsupported/unobserved control stays unqualified.
No promotion, rule deployment, provider probe or model call was performed.
