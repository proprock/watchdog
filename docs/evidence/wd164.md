# WD-164: Codex execution lifecycle and outcomes

Date: 2026-10-15. Implemented in `feature/wd-164-execution-lifecycle`.

## Behavior and evidence boundaries

`execution.normalize_events` derives `wd-164.v1` execution facts from authoritative
hook and rollout envelopes. `analysis.tool_outcome`, session state, materialized
reports, error inspection, token insights and tool timelines use that projection.
Stored native input and output remain unchanged and obey content capture/retention.

- Native project/session/agent/call identity joins hook `Bash` and rollout
  `exec_command` observations. `cmd` and `command` share a command projection;
  native argument arrays remain arrays and can identify a finished test runner.
- A yielded execution remains waiting. Native execution session IDs connect
  `write_stdin` polls to the original command; repeated polls add evidence, not
  completed commands. Missing or ambiguous identity never uses command text or
  timing as a substitute correlation key.
- Structured exit/error/cancellation fields and leading provider result frames
  establish outcomes. Command output after the output delimiter cannot supply
  a verdict. Incompatible terminal results become unknown with provenance.
- `apply_patch` and explicit native `FileChange` records identify edits. Nested
  code-mode `CommandExecution` records expose command, native item ID, status and
  exit evidence independently of the opaque outer `exec` body. A completed outer
  script alone has an unknown command outcome; JavaScript text is never executed
  or parsed to manufacture child commands.
- The existing daemon-only durable reader emits raw starts/finishes from
  `response_item` and explicit execution/edit records. Tool grammars are bounded
  to fixtures for `0.153.4`, `0.160.0` and `0.162.0-alpha.17.2`; the last version's
  nested item field shapes were also inspected locally without provider calls.
  Other versions emit an unavailable tool-enrichment gap while usage continues.
  Missing call identity or mismatched native thread identity produces a gap.
- Partial lines, restart, truncation, alternative path spelling, old-reader
  backfill and duplicate delivery preserve usage and tool receipt identities.
  Disabled or oversized content stays unavailable, with oversized omission
  provenance, rather than stopping later usage records.
- Late enrichment replaces derived facts at the original hook completion
  position. A late duplicate start cannot reset a newer turn. Yielded completion
  uses its terminal poll's position, so it cannot verify a subsequent edit.
  Codex verification requires a completed, known result and captured test command;
  running, cancelled, unknown or uncaptured commands cannot prove verification.
  Existing Claude classification and verification behavior remains covered.

The narrow `state_projection_versions` marker rebuilds only Codex state caches
once for this projection. Events and schema-v8 authority are unchanged. Replay
can derive counters only from retained evidence; expired history cannot supply
missing facts. Ordinary Codex hook updates replay the affected conversation agent
inside the daemon. Rollout reader windows defer that replay until their raw observations
are stored, once per affected agent. A dirty identity commits with each native
event; interruption or failed replay leaves it durable, and opening the store
repairs it before serving state. Marker removal and repaired state commit
together. Duplicate receipts cannot create dirty ghosts; purge/retention prunes
markers. The first local deployment exposed quadratic per-event replay during
backfill and exceeded the CLI's 10-second startup acknowledgement. The daemon
was stopped normally and this reader-window fix was verified before redeployment.
Synthetic deferred writes plus replay took 0.916 seconds for 200 observations
and 4.611 seconds for 1,000, compared with 3.55 seconds for the earlier immediate
200-observation path. These are local storage measurements, not hook latency or
live-provider effect measurements.

Statistical rule bodies and `REPETITION_THRESHOLD` are unchanged. Codex findings
record the execution projection and native evidence IDs, and bind fingerprints
to that projection so old verdicts are not silently reused. WD-161/WD-167 still
own polling calibration and user verdicts; WD-162 owns general state/findings
invalidation. This task neither measures precision nor opens a control capability.
