# WD-164: remove `policy_intervene_same_model_subagent_spawn`

The user asked on 2026-10-09 to drop the WD-022b per-rule switch, which WD-142 had kept
as an alias for `subagent_same_model`. Two switches remain, and they are the only ones:
`policy_intervene` (global in `[defaults]`, per project in `[projects.overrides]`; neither
can undo the other) and `rules disable <name>` for one rule by name.

- `Limits` and `Overrides` lose the field, and `rules/engine.py` loses `_LEGACY_SWITCH` and
  its check. The models are strict, so a configuration that still sets the key is now
  rejected as an unknown key (covered by `test_the_removed_per_rule_switch_is_rejected_as_an_unknown_key`).
  `config.example.toml`, `docs/rules.md`, `docs/architecture.md` and `docs/provider-compatibility.md`
  no longer describe it.
- Removed the legacy-switch parametrized test in `tests/test_daemon.py`; the contract test
  for the kill switches that remain is unchanged.
- The user-local configuration had the key; it was removed first and the file still loads
  with the new code (5 projects, `policy_intervene = false`).
- Verification: full `uv run pytest` 1238 passed, 1 skipped; ruff and ty clean.
