# WD-174: Restore provider ingestion and expose coverage loss

Completed: 2026-10-23. All timestamps below are UTC.

## Incident and implementation

After the 2026-10-18 daemon restart, the real Claude adapter still wrote spool
schema 1 while the daemon required schema 2. Codex desktop's MSIX filesystem
virtualization had redirected an adapter update to the packaged copy. The real
adapter was restored from a non-packaged process on 2026-10-20 at 19:40;
Claude events resumed and the adapter `invalid` counter stopped at 2,398.

Commits `74ba6c4` and `e2ee088` added the offline diagnostics:

- The spool persists rejected schema versions, the expected version and the last
  rejection time in `schema-mismatch.json`.
- `doctor` exposes `adapter.schema_mismatch`, warns with
  `adapter_schema_mismatch` and sets `ok: false` for a mismatch in the last 24 hours.
- `daemon status` exposes `health.schema_mismatch` and degrades with reason
  `adapter_schema_mismatch` for the same window.
- `doctor` compares recent provider transcript activity with stored provider
  events. Active transcripts without an event in the 24-hour window produce
  `provider_transcripts_without_events`. This is a warning: unregistered projects
  also create transcripts. Missing transcript roots remain unknown. This scan
  runs in `doctor` only.

The ignored `LIVE.md` procedure requires checking both adapter hashes and one
fresh event per provider. A check made inside the MSIX context can open the same
virtualized file for both path spellings, even when
`GetCurrentPackageFullName` reports no package identity. A launch through
`Shell.Application` also retained this redirection here. Handle-resolved physical
paths from the WMI-launched process established that the final hash comparison
actually read both files.

## Backfill decision

The 2026-10-23 decision in `c761162` remains: do not backfill the nine missing
Claude sessions from 2026-10-18 through 2026-10-20. Transcripts could restore
usage and tool facts, but not the complete turns, permissions or control record.
The historical gap remains explicit; no backfill command or discovery was added.
