# WD-223 verification

## Finding and decision

All 51 reported dimension/session differences across 17 Codex parent sessions
are numerically explained by historical child receipt coverage and the existing
source/store accounting conventions. No current parser or collector defect was
verified. Production accounting, raw records, historical receipts, installed
databases, and provider configuration were not changed.

Insights aggregates the imported child sessions named by `parent_session_id`.
Watchdog reconciliation aggregates parent-session usage facts with a child
`agent_id`, deduplicating native response IDs within each project store. The
same response retained in two stores contributes once in each store. Native
`thread_token_usage` deltas include compaction usage that can be absent from
`event_msg.token_count` notifications, as also verified in WD-222.

Changing either convention merely to eliminate discrepancies is not justified
by this investigation. Historical receipt routing/coverage provenance remains
an explicit follow-up, WD-225; replay does not establish why old hooks are absent.

## Read-only source verification

The original WD-195 snapshot was opened read-only. Repeating reconciliation
exactly reproduced all 204 Codex subagent dimension rows: 51 parents times four
dimensions, including unavailable comparisons. No model or provider probe ran.

The snapshot names 98 children across these parents. All 98 retained source
streams were inspected (20,463 records). Each first record names the expected
child and its `parent_thread_id`; its `session_id` also matches the parent.
Every historical import cursor and byte count matches a retained source prefix,
and parsing that prefix exactly reproduces all three historical child totals.
One three-record child has no usage; its unknown totals were not treated as an
observed zero.

The 21 comparable parents have 77 children. Only 42 children have usage receipts
under those parents; the other 35 contribute 42,492,437 input, 39,846,144 cached
input, and 73,003 output tokens to historical Insights. Sixteen comparable
parents have this coverage difference. For all 56 children without receipts
across the 51 parents, the snapshot also has no child-attributed hook facts and
no usage facts filed under another session. This describes the historical
snapshot, not an exhaustive claim about all hooks ever delivered.

For the 42 covered children (8,753 records), every distinct historical native
response ID occurs in the captured source and every source ID has a receipt.
Forty children have identical notification and receipt totals. One child's
native compaction response adds (278,045 input, 274,688 cached input, 2,241 output)
without a corresponding notification. Another child's 80 native responses occur
in two project stores with identical usage tuples in both; the second store adds
(6,394,497 input, 6,295,040 cached input, 15,511 output). First-copy handling was
verified within each store. Zero-valued extra notifications add no tokens.

The complete historical Insights-minus-Watchdog decomposition is verified for
each comparable parent, including below-threshold contributions:

| Contribution | Input | Cached input | Output |
| --- | ---: | ---: | ---: |
| Imported children without parent-attributed receipts | 42,492,437 | 39,846,144 | 73,003 |
| Native compaction absent from notifications | -278,045 | -274,688 | -2,241 |

The 30 unavailable parents comprise 18 with no imported children or child usage
receipts, and 12 with 21 imported children but no child usage receipts. Their
unavailable comparisons remain unavailable. Cache-write usage is unavailable
for all 51 parents.

## Current-reader replay and repeated comparison

All 98 retained child streams were replayed through the current collector in
isolated temporary stores, using child rollout filenames and parent hook session
IDs. Bounded reads drained to EOF, and event pagination found exactly 2,048 usage
events, one per native response. Every usage event had the expected child
`agent_id`; all cumulative-delta totals matched the native source totals. The
only gap diagnostic was `tool_version_unsupported`; no usage failure occurred.
This does not qualify tool/control grammar support. Temporary stores were
removed; source stores and the historical snapshot stayed read-only.

Fresh parser totals also cover all 98 streams. One uncovered child has 97
retained records beyond its historical 240-record import cursor. Catching up
adds (657,323 input, 634,752 cached input, 842 output) to Insights. The repeated
comparison still has 17 differing parents in each known dimension:

| Dimension | Historical Insights | Watchdog | Fresh parser, all children | Historical >1% | Fresh >1% |
| --- | ---: | ---: | ---: | ---: | ---: |
| Input | 116,571,794 | 80,751,899 | 117,229,117 | 17 | 17 |
| Cached input | 111,041,280 | 77,764,864 | 111,676,032 | 17 | 17 |
| Output | 421,950 | 366,699 | 422,792 | 17 | 17 |
| Cache write | unavailable | unavailable | unavailable | 0 | 0 |

Totals include only the original 21 comparable parents. The 30 unavailable
parents are excluded; fresh parser coverage does not create missing receipts.
As a separate diagnostic, restricting fresh parser totals to the 42 children
with receipts yields (74,079,357 input, 71,195,136 cached input, 348,947 output).
Only two parents then differ above 1% in each dimension, exactly the compaction
and two-store cases. This restriction is an analytical comparison, not a change
to doctor, stored data, or either accounting convention.

Ignored reproducibility artifacts are `tests/local/wd223_reconcile.py`,
`tests/local/wd223_replay.py`, and `tests/local/wd223-live/` (detailed report,
replay results and log). Real transcripts, session IDs, private project names,
and machine paths are not committed.
