# WD-195 verification

## Delivered behavior

Read contract v1 now documents and exposes paged `events` and `event_facts`
readers. They release each read transaction before yielding and stop at the
source event high-water mark observed at iterator start. Facts use their parent
event rowid. Both readers reject unsupported contracts and schema mismatches.

Normal `wdi import` copies hook records, including event-only stores, into
derived `hook_events` and `hook_facts` tables. Identity includes machine and
project; each store's records and shared `wd-facts://` cursor commit atomically.
Imports are incremental and idempotent; `--full` rebuilds the projection.
Late model/effort attribution changes require `--full` until WD-220 is done.

`wdi sessions show` reports observed permission waits, tool durations, and
delivered action/rule counts. Incomplete waits and missing durations remain
unavailable. `wdi doctor` compares four token dimensions separately for main
and subagent usage, lists differences above 1% of Watchdog, and prints totals
only for pairs known on both sides. Codex usage comes from transcript `event`
rows; Claude usage comes from assistant rows. Native usage duplicates use the
first copy within their source store, matching Watchdog's convention. A missing
dimension in any contributing usage row makes that dimension unavailable.

## Installed instance

running Insights client, `scripts/wd195_convert_insights.py` converted the
installed database from revision 2 to 3. A timestamped SQLite backup beside the
database retains revision 2. The converter adds derived hook tables without

all 1,878 sessions and 60 saved analyses were retained. `PRAGMA quick_check`
