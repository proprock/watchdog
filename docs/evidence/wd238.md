# WD-238 evidence

The [Windows scratch-store diagnosis](wd237.md) reproduced the callback-loss signature with an injected 600 ms admission-lock hold. A focused regression then attempted a second real admission acquisition from inside Python spool `fsync`. It failed with `WriterBusy` on the old publisher, demonstrating that slow sync exposed native callbacks to contention even after the native publisher's own sync was moved out of the lock.

Python now reserves the exact byte count and a file slot under admission, writes and syncs outside admission, and promotes under admission using the remainder of its 100 ms wait budget. Its temporary file stays charged to both quotas until promotion or failure. The tested competing publisher can obtain the lock during sync and is refused when the staged record occupies the last slot. The disk-full check also verifies removal of the unpublished reservation and a recorded I/O loss.

The focused spool, retention and atomic-write modules passed all 20 tests. The 62 parallel native tests covering timeout clamping, desktop profiles and the scratch-store round trip also passed.

The full Windows suite with `WATCHDOG_REQUIRE_NATIVE=1` passed with 2,195 tests and one skip. Ruff lint, Ruff format verification and ty passed.

Both packages built successfully. The local Watchdog wheel was reinstalled and the daemon acknowledged a restart. Both installed native binaries matched the release build. The restarted daemon reported `running`, and `doctor` reported no warnings or schema mismatch. A bounded SQLite read found four fresh Codex hook events and no fresh Claude event at the time of verification.
