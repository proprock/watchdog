# WD-231: capture readiness and policy discovery publication

The [WD-226 investigation](wd226.md) identified independent capture readiness
and Windows policy discovery access windows. The transcript test now waits
for an empty, unversioned database to finish initialization before opening the
capture store. Nonempty unversioned and incompatible-version databases still
raise `StorageError`. The daemon still creates the database, and the test
continues to require the exact captured transcript bytes.

Initial policy publication and subscription updates use the existing
shared-reader replacement path. Readiness and the affected adapter test read
the discovery document with the matching shared-read helper. The native
adapter retains its existing fail-open behavior. Windows filesystems that do
not support the shared replacement primitive retain its existing fallback;
non-cooperating readers can still prevent replacement.

Two Windows regressions held a cooperative reader open during initial
publication and subscription replacement. Both failed before the production
change and passed afterward, including checks of the old reader snapshot and
new discovery content. A controlled SQLite test failed on version 0 before
the readiness change and passed after it. Separate tests reject incompatible
and nonempty unversioned schemas; the latter was added after review.

Verification on Windows:

- Focused policy, adapter and readiness tests: 45 passed. Final capture and
  policy regression selection: 6 passed.
- Final `uv run pytest`: 2,165 passed, 1 skipped in 155.13 seconds.
- Ruff check, Ruff format check, ty, and `uv build --all-packages` passed.
- The existing release adapter build succeeded; a separate WMI process
  confirmed that the real and packaged installed adapter paths resolve to
  distinct files and both match the release hash. The identical binaries
  were not replaced.
- The owned installed wheel was reinstalled, the daemon restarted and
  reported running. Synthetic Codex and Claude transport/admission checks
  passed and purged their records; doctor reported no warnings or schema
  mismatch. Fresh real provider hook rows after restart were not verified;
  WD-232 tracks that remaining installation check.
- TDD tests were observed failing and passing at the paired commits. The
  structural TDD auditor rejects test-only green commits despite the fixes
  being test infrastructure; WD-233 tracks this limitation. Its `--run`
  mode creates worktrees, which repository policy requires explicit user
  authorization to create, so that mode was not run.
