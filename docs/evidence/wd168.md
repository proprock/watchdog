# WD-168: Control delivery observability

Date: 2026-10-16. Scope: offline daemon/adapter observability and reporting.

## Contract

- A selected control decision survives a socket write failure. `selected_at`
  records selection; `response_sent_at` and historical `delivered_at` mean socket
  send only and remain null when sending fails or the action is unavailable.
- The native adapter uses the existing hook spool record to acknowledge a
  compatible response and local rendering. It adds no acknowledgement socket,
  wait, or provider call. Control evidence persists with timing telemetry off.
- Findings correlate the acknowledgement by hook event ID and action. Missing
  acknowledgement remains unknown. Rendering is not stdout consumption or an
  independently observed provider effect.
- Unsupported requested actions produce bounded control capability gaps and
  allow the harness to proceed. Disabled and unsubscribed traffic does not
  become a successful attempt. Statistical findings are not invented.
- `rules stats` separates attempted, response-sent, rendered, unknown-stage and
  capability-gap coverage. Legacy send records do not gain inferred effects.
