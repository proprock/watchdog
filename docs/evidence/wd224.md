# WD-224: native spool admission under Windows disk load

The original [WD-220 run](wd220.md) saved seven of eight events and recorded
one `busy` loss. A controlled Windows reproduction showed that durable spool
writes can keep `admission.lock` occupied longer than a competing adapter's
250 ms wait. The original run retained counters but no timing trace, so its
individual lock owner and the operation that delayed it remain unknown.

## Reproduction and measurements

Each stress trial used a fresh spool, eight synthetic Codex callbacks, four
concurrent invocations, and the daemon ownership lock from `native_setup` to
prevent daemon startup. The trials exercised the release adapter through the
same subprocess helper as the failing test. Independent trials shared the
host and disk but used separate admission locks.

| Adapter and workload | Saved | Trials with losses |
| --- | ---: | ---: |
| Stock, 1 and 4 concurrent trials, no background writes | 800/800 | 0/100 |
| Stock, 8 and 16 concurrent trials, no background writes | 896/896 | 0/112 |
| Stock, 4 concurrent trials and 4 background writers | 712/768 | 34/96 |
| Instrumented, same disk workload | 704/768 | 39/96 |

Each background writer repeatedly overwrote and synchronized its own 1 MiB
temporary file until the trials finished. Several stock trials saved seven
files and had exactly one `busy` loss, with the other four loss counters zero.

A temporary release build timed lock wait, directory scan, publication,
and guard drop. It printed timing data after releasing the guard. All 64
missing events in that run had a `busy` trace and a matching aggregate counter.
Twelve successful publications in trials with losses held the guard for more
than 250 ms. The longest hold was 449 ms, including 277 ms in `sync_all`,
127 ms in temporary-file creation and write, and 42 ms in file close. The
directory scan took 0.12 ms in that hold. `sync_all` accounted for more than half
of the measured hold in 606 of 704 publications. No rename retry occurred.

In a second diagnostic comparison, two 320-call batches with `sync_all`
enabled saved 315 and 257 events. Two intervening batches with just the
adapter's `sync_all` bypassed saved all 640 events and emitted no `busy`
traces. Background flush counts varied between batches, so the comparison
does not establish a loss rate. The diagnostic bypass was confined to the
temporary build. The on-disk spool still requires durable publication.

## Disposition

The controlled reproduction is consistent with the documented admission
contract. The adapter holds the shared lock through footprint measurement and
durable atomic publication, and waiters can return fail-open while a competing
writer is still committing. The existing `test_native_admission_lock_contention_records_busy`
deterministically covers expiration while a writer holds the lock. The
investigation found no separate lock or quota implementation defect requiring
a new regression for the current contract. WD-228 tracks reducing loss while
preserving durability, shared quotas, and bounded hook latency. It requires a
deterministic regression for whichever publication change it adopts.
