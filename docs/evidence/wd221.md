# WD-221 verification

## Finding and decision

The five Claude subagent output differences and the one cached-input difference
in WD-195 come from immutable historical first-block usage receipts. They are
not evidence of a current Insights accounting defect. No production accounting,
raw records, historical events, or installed databases were changed.

The current collector already waits for a completed response, a later request,
or a bounded stalled/oversized fallback. Commit `534aa81` introduced that behavior
on September 26, 2026 and explicitly preserved older receipts. A receipt alone
does not identify the reader version that created it; the verified claim here
is that its counters equal the first raw block. Current stalled/oversized
fallbacks can also preserve incomplete values and remain documented limitations.

## Source comparison and replay, November 13, 2026

The original WD-195 Insights snapshot was opened read-only. Its reconciliation
was repeated and exactly matched the saved Claude subagent comparison, including
unavailable dimensions. The same five affected parent sessions contained 19
subagent streams and 197 distinct native request IDs. Every ID was present in
both the historical usage facts and the captured raw transcript.

For every one of these requests, all four historical token counters equaled
the first raw response block. Grouping by `requestId` and selecting the final
raw block produced exactly the saved Insights message totals in each stream.
This explains the complete differences: 100,672 output tokens, 139,014 cached
input tokens, two input tokens, and 2,965 cache-write tokens. The latter two
differences were below WD-195's 1% reporting threshold.

All 19 captured streams were also replayed through the current production
collector into fresh temporary stores. Two enrichment passes produced exactly
197 usage events, with all four counters equal to Insights per stream. Source
stores and the snapshot remained read-only. This used no model or live provider
probe. Temporary stores were removed after replay.

## Regression coverage and verification

Two synthetic tests cover simultaneous growth of input, cached input, cache
write, and output from `(2, 100, 10, 3)` to `(4, 250, 20, 116)`:

- `tests/test_claude_transcripts.py::test_subagent_final_block_updates_every_usage_dimension`
  verifies the collector holds an unfinished subagent response across read
  windows and emits exactly one final usage event.
- `insights/tests/test_ingest_claude.py::test_subagent_fragments_completed_in_later_import_reconcile_all_usage`
  verifies incremental import reconciles messages and model calls, preserves
  both fragments and source bytes, and leaves an unchanged reimport idempotent.

These characterize an already implemented fix, so no artificial failing test
or production red/green change was introduced. Existing tests also preserve an
earlier receipt when a replay later sees larger counters.
