# WD-175: Provider-aware cached-input pricing

Completed 2026-10-23.

Codex includes cache reads in `input_tokens`; Claude excludes them. Pricing now
uses `max(0, input_tokens - cached_input_tokens)` for Codex full-rate input and
keeps Claude's convention unchanged. Cache reads are priced once. Provider
identity is selected for every grouping, including model and day. Billable
token counts and unpriced-token accounting use the same convention; raw stored
counters and raw usage aggregates remain unchanged.

A missing Codex cached counter leaves its input unpriced, with
`cached_input_unavailable`, while independently known output is still priced.
It does not turn the missing counter into zero. No database migration is needed;
historical estimates are recomputed on the next report.
