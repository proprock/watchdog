# WD-230: Codex Desktop guardian review probe

On 2026-11-14 the user authorized one live Desktop probe. A harmless request to
read the system time outside the sandbox triggered the automatic approval
review. The provider archive recorded one completed `guardian_review` child
of this Desktop thread at 06:07:26–06:07:30 UTC. Its metadata reports the
Watchdog workspace as its working directory, Codex Desktop as originator, and
backend `0.167.0-alpha.4.1`. It contains one native usage record. The
installed Desktop package reports version `26.1106.6628.0`.

The installed native adapter reported `0.1.5`, decision schema 2, with SHA-256
`c02308ca9f8eb600e859c6d25ac6044f8390e238eeecdcce53a0de7899850831`.
Read-only queries across all 16 project event stores found parent hook events
around the probe and one registered parent transcript source. They found no
event whose session ID is the guardian child and no transcript source whose
session ID or path identifies it. The child ID appeared in parent tool records
only as text in this investigation's own commands and output; those are not
child callbacks. No child ID appeared in the available Watchdog log or the
spool at the initial check. Queries used SQLite read-only mode with WAL access;
all 16 stores opened successfully.

This establishes a provider-side child and a working parent hook-to-store path,
not the point at which a child callback might have been lost. The installed
adapter has no independently observed ingress record in this probe, and the
provider's callback emission was not independently instrumented. Consequently,
the absence of a retained child callback cannot distinguish non-emission from
delivery or ingestion failure. No child callback supplied a transcript path or
working directory to evaluate for registration. The provider metadata working
directory alone does not establish those callback fields. At this point an
ingress-observable probe remained necessary; no provider capability is inferred
from this single review.

## Ingress probe preparation

With separate authorization, prepared a scratch Git project and isolated
Watchdog configuration. Its project-local hook records selected ingress fields
before forwarding the unchanged input to the installed native adapter. No
control rules are approved in the scratch configuration. A synthetic adapter
check verified input and output bytes and a nonzero exit code; a synthetic
`SessionStart` also reached the production adapter and produced a spool record.
The project hook SHA-256 is
`01421b0a3b10db19f5094bec0f76f1c81029e285f423eb353b9c7a424ccaff28`.
The user reviewed and trusted this hook and ran the requested command in a
fresh Desktop chat. The owned hook was subsequently disabled by renaming it,
after verifying the hash. Scratch artifacts and the trust record are retained.

## Ingress probe result

On the same Desktop package and backend versions, the provider archive recorded
one completed guardian child of the scratch chat at 06:28:43–06:28:46 UTC.
The child metadata names the scratch working directory and contains one native
usage record. The wrapper recorded six parent callbacks: `SessionStart`,
`UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, and
`Stop`. Each contained the scratch working directory and a transcript path;
six parent hook events and one parent transcript source were subsequently found
in the isolated store. The earlier synthetic baseline was separately identified.

No wrapper record identified the guardian child, and no `SubagentStart` or
`SubagentStop` callback was recorded. The isolated store contained no event or
transcript source naming the child. The spool had drained; its remaining JSON
file was pipeline telemetry. These observations establish that the trusted
project hook and the adapter-to-store path worked for the parent during this
one run, and that no child callback was recorded at this wrapper's ingress.
They do not establish whether the provider emitted a guardian callback, whether
it routed one to this project hook, or whether an unrecorded invocation failed
before the wrapper could write its record. No child callback fields were
available to evaluate transcript-path or working-directory registration. The
provider rollout's working directory is not a substitute for those fields.
WD-230 remains open for that unresolved boundary; this observation does not
establish a general capability for other versions or installations.
