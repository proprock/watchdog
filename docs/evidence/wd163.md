# WD-163: Codex CLI control probe corrections

The sanitized records in [wd163-codex-cli-control.json](wd163-codex-cli-control.json) contain 32 live-provider attempts: 13 supported, 2 unsupported, and 17 inconclusive capability assessments. Every attempt records confirmed cleanup. These probes called the provider directly and did not exercise Watchdog persistence (`expected_deliveries`, `persisted`, and `read_back` are zero); callback counts and the provider-side effect checks below are separate evidence.

The initial two attempts ran Codex CLI 0.160.0 because the elevated process resolved a different executable through `PATH`. Later attempts ran 0.162.0-alpha.17.2. All used Windows and model `gpt-6.1-sol` at low reasoning effort. Noninteractive cases used `codex exec`; the listed interactive cases used the CLI TUI. Each attempt was explicitly live and bounded by the probe timeout (120 seconds by default). Runs used an isolated Codex home and a scratch Git repository outside registered projects. The hook-trust bypass flag was confined to that isolated home. The final runner marks only the scratch project as trusted; the first attempts preceded that configuration fix. The final patch rewrite required an operator-approved edit to that scratch file. The owned process tree, isolated home, and scratch state, including the temporary authentication copy, were removed in every record. Where retained, raw diagnostics remain under ignored `tests/local/`.

The two unsupported assessments are distinct: the superseded loose-prompt `SubagentStart` attempt and the `PreCompact` response envelope. The corrected `SubagentStart` workload later passed. The `PreCompact` callback itself is confirmed, while its context response is unsupported. `PostCompact` remains inconclusive because the callback, rejected response, missing follow-up marker, and timeout do not establish a completed effect assessment.

The corrected `apply_patch` response uses `hookSpecificOutput.updatedInput.command`, as required by the current contract. The five headless corrected attempts remain inconclusive; only the interactive attempt established the rewritten file contents. This does not establish broad support across CLI versions or tool paths. The `ask` observation likewise remains inconclusive. The local-tool and code-mode gaps remain scoped to the exact tested runner and policy conditions.

Reproduce an individual case in a fresh scratch location with:

```powershell
uv run python scripts/codex_control_probe.py --live --codex PATH --case NAME --output NEW.json [--interactive]
```

Use a new output file per attempt. The `--live` flag is required because each invocation spends provider quota; interactive cases require an operator for TUI actions such as manual compaction or Escape. These records do not enable daemon or native-adapter permissions. WD-151 must apply its independent surface/version and per-cell gates before any renderer is enabled.

The callback records confirm `tool_input.command` is a string for `apply_patch` and the corrected response replaces that field. The final sentinel check, rather than a model claim or a token found in a hook payload, establishes the patch effect. The MCP rewrite checks also read the actual fixture sentinel. Only the named local fixture and observed `exec` wrapper were exercised; these results establish no hosted-tool coverage.

`scope.callback_minimums` states the required minimum per event. Callback totals include additional observed provider invocations instead of clamping them to that minimum. Aggregate records add only sanitized same-run tool-path/permission facts and requested-model provenance. The [final runner smoke record](wd163-pre-tool-mcp-rewrite-attempt-3.json) is also retained individually; it is the same attempt as the last aggregate entry and must not be counted twice. That smoke confirmed the gated launcher, MCP rewrite, and cleanup. The launcher waits for job assignment before starting Codex, passes standard streams explicitly, and confirms zero active job processes before removing scratch state.
