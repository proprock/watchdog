# WD-177: Codex desktop `PermissionRequest` deny and permit

Date: 2026-10-24. Scope: Windows Codex desktop app `26.1016.62342`, backend
`0.163.0-alpha.11.2`, cells confirmed by [WD-153](wd153.md). Offline only; no live
desktop run and no local instance change.

## Decisions

- `deny` reuses the existing action. `permit` is a new action, distinct from `allow`
  (no opinion, always silence). TENETS.md was changed with the user's explicit
  authorization to list it and to constrain it: a rule must name its tool, and it is
  deliverable only for a confirmed `PermissionRequest` cell on an exact profile.
- `PermissionRequest` becomes an observed Codex event of kind `waiting`, the Codex
  counterpart of Claude's `Notification`. The installer registers it; an older
  ownership record (without it) is still accepted for uninstall and is completed by
  the next install. Readiness reports `hook_events_outdated` until then.
- An adapter that predates `permit` rejects the unknown action and fails open.

## Cells added to the desktop profile

`PermissionRequest`/`Bash` `deny` (`decision.behavior = "deny"` with `message`) and
`permit` (`decision.behavior = "allow"`). `PermissionRequest` with `apply_patch`, and
`ask`, `rewrite` or `context` on it, are not promisable by any rule.
