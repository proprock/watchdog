# WD-160 - PowerShell destructive-command coverage

Date: 2026-10-16.

Declarative rules accept either an exact `match.tool_name` or a nonempty
`match.tool_names` list. Empty names and conflicting selectors are rejected.
Matching, capability validation, engine filtering, rule inspection, and adapter
subscriptions all honor the list. Subscriptions are deduplicated per tool rather
than broadened to every tool.

The shipped `destructive_command` rule is version 3 and watches both `Bash` and
`PowerShell`. Its existing Git and shell alternatives are preserved. It also asks
about `Remove-Item` with `-Recurse` and deletion of `.env` files, including quoted
Windows paths and `-LiteralPath`. Cmdlet and `-Recurse` spelling is case insensitive.
The existing textual matching tradeoff remains: a quoted destructive command can
ask, and this is not a complete shell parser.

- The existing daemon discovery test now expects the added PowerShell cell;

- Ruff lint and format, `uv run ty check`, `uv build`, and diff hygiene passed.
- Final full offline suite: **1605 passed, 1 skipped** in 98.74 seconds

## Local installation

The verified wheel was reinstalled and the stable native adapter was refreshed.
The old daemon stopped; the replacement reported `running` with no reasons,
errors, or warnings. The start command initially returned a failure before the
new process settled; a subsequent status check confirmed its new PID and health.
The installed rule reports version 3 and both tool names; the stable adapter hash
matches the repository release artifact.

The existing live configuration has global intervention disabled
(`policy_intervene = false`), so live discovery correctly publishes no control
subscriptions. That setting was preserved. PowerShell subscription and `ask`
delivery are verified in the isolated real-daemon tests, without enabling live
intervention or running destructive commands.
