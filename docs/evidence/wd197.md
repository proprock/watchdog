# WD-197 verification

`wdi analyze`, Coach, and Context Advice use the Watchdog Claude runner for
free-text completions. The runner sends the prompt over stdin, uses a scratch
directory outside registered roots, and disables session persistence. The
adapter translates runner failures into `LLMError` and preserves the 180-second
completion timeout.

## Offline verification

- Synthetic CLI tests exercise the isolation flags, a 200 KiB UTF-8 prompt,
  refusal for registered and unresolvable roots, and refusal of Windows batch
  launchers. The scratch directory is removed after completion.
- Four concurrent calls share one preflight. A changed executable modification
  time triggers another preflight. The existing web tests passed unmodified.
- The Insights suite passed 308 tests with one Starlette deprecation warning.
- The Watchdog suite with `WATCHDOG_REQUIRE_NATIVE=1` passed 2,190 tests with
  one skip.
- Ruff lint and formatting, ty, and both package builds passed.

--workers 1 --yes`, the Claude backend, and model `haiku`. The input database
contained exactly one synthetic session; provider-directory and Watchdog
imports were disabled except for that synthetic source. The runner used the
real Claude Code 2.1.323 executable, with a 180-second completion timeout.

or isolated Claude process remained. The import-only database was preserved
locally. The corrected harness asserts the sole synthetic session and checks

The observed flags included `--safe-mode`, empty `--setting-sources` and
`--tools`, `--strict-mcp-config`, and `--no-session-persistence`. The scratch
directories were outside registered checkouts and were removed after return.
