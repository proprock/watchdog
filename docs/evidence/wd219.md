# WD-219 verification

## Failure and decision

WD-197 observed a failed Claude analysis (HTTP 429) while `wdi analyze` returned
status 0. The CLI displayed `AnalysisStats.failed` without using it for the exit
status. The Claude backend also discarded the isolated runner's redacted error
details, retaining only its generic failure reason.

Any failed attempted analysis now makes the command exit with status 1, including
a partially successful batch. Processing continues across sessions and analyzers;
successful results remain stored, and the results table is printed before exit.
Existing successful no-op paths (disabled analysis, no work, cached selection,
or declined confirmation) remain unchanged.

Claude errors retain their generic reason plus bounded, selected diagnostic
fields: API status, terminal reason, subtype, result, stderr and fallback stdout.
Text fields come from the runner's existing redaction. Unrelated provenance,
including executable arguments, is not included. The shared runner also retains
the error-envelope details when Claude exits zero but sets `is_error`. CLI
diagnostics disable Rich markup so bracketed provider text is displayed literally.
