# WD-156 - Live-provider evidence for the decision channel's rendering, and a reloaded request budget

## Reloaded request budget

`payload_bytes` now reloads on a running daemon. `_Channel.sync` compares the budget with the published
`max_request_bytes` on every poll tick. A changed budget moves the server's read limit and the discovery file
together: a raised limit is applied before publishing, a lowered one only after the file is written, so the
server never reads less than the file promises. A failed publish keeps the previous file and, for a lowering,
the previous server limit.

Running-daemon tests in `tests/test_daemon.py` (commit `3bb2137`):

- `test_a_reloaded_payload_budget_moves_discovery_and_the_server_read_limit` raises and lowers the budget on a
  live `_policy_server`, reads the updated discovery file each time and sends requests just inside and at the
  old and new limits. A request past the old limit is answered after a raise; one at the new limit is dropped
  after a lowering; token and port stay valid.
- `test_a_failed_budget_publish_keeps_the_server_limit_in_step_with_the_file` covers a failed publish.
- Fail-open behavior is unchanged: an oversized request is dropped and the adapter proceeds as if Watchdog were
  absent.

## Adapter-rendered live probes (Claude CLI and desktop)

`scripts/live_probe.py adapter-control` (CLI) and `desktop-prepare --adapter` / `desktop-collect` (desktop) run
the production native adapter (`agent-watchdog-hook 0.1.5`, decision schema 2) against a real daemon in a
scratch instance (own config, data and runtime) with one approved user rule per cell. A recording wrapper logs
each callback and relays the adapter's stdout, stderr and exit status unchanged. Prompts and judges are the
WD-139 `claude-control` ones. Built-in rules are disabled in the scratch instance. No scratch instance touches
the user's configuration or registered projects.

| Cell | Rule | Claude CLI 2.1.292 | Claude desktop 2.1.299 |
|---|---|---|---|
| `PreToolUse` deny (`Bash`) | `deny` on a matching command | supported | supported |
| `PreToolUse` rewrite (`Agent` `model`) | `rewrite` `tool_input.model` to `sonnet` | supported | supported |
| `PostToolUse` context (`Bash`) | `context` token read back from the reply | supported | supported |
| `Stop` block | `block` once per turn; a second `Stop` carries `stop_hook_active` | supported | supported |

- CLI records: [wd156-claude-cli-adapter.json](wd156-claude-cli-adapter.json), main model Haiku, 2026-10-20.
- Desktop records: [wd156-claude-desktop-adapter.json](wd156-claude-desktop-adapter.json), main model Haiku, one
  chat per cell armed by a `WD156[<case>]` prompt prefix. The routed wrapper forwards only the armed cell's
  events, because all four rules are approved at once.
- Rewrite is judged by the models in the subagent's own transcript (`subagents/agent-<id>.jsonl`), since the
  parent transcript carries no per-model usage. A `claude-sonnet-*` subagent after a `haiku` request proves
  the substitution reached the provider.
- Cleanup was confirmed for every record. `taskkill /T` stops the daemon tree because a venv launcher spawns
  the real interpreter.

## Limits

- One Windows host, one CLI and one desktop version, Haiku main model, one prompt per cell.
- Rendering is proven for these four cells only; `ask`, `SubagentStop`, `PreCompact` and the other cells keep
  their WD-139 status.
- The wrapper sits between Claude and the adapter, so adapter start-up time as seen by the provider is not a
  measurement here.
- Codex production-adapter evidence belongs to WD-151.
