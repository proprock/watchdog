# WD-189 verification

The daemon creates one UUID4 per data directory and publishes versioned project
manifests during its normal project visits. The read API checks the contract and
database versions, reads byte-exact capture records in short transactions, and
lists no transcripts for a project without a capture database. See the
[read contract](../read-contract.md).

## Offline checks on 2026-11-12

- The new cases failed before implementation. The review regression also failed
  against the initial reader when SQLite reused the key of a purged stream.
  The final reader detects replacement before reading another page. The focused
  run passed 25 cases, including checkpoint progress during a suspended read.
- An initial full run found a timing failure in the existing doctor capture
  fixture. Its saved database had schema v1 and zero stream rows. The fixture
  now uses a fixed clock because it exercises the report's counters.
- `uv run pytest` with `WATCHDOG_REQUIRE_NATIVE=1` passed 2151 tests with one
  skip in 127.66 s. `uv run --directory insights pytest` passed 263 tests and
  reported a Starlette test-client deprecation warning.
- Ruff lint and format, ty, `uv build --all-packages`, and `git diff --check`
  passed. Importing `readapi` did not load the daemon or inspection modules.

## Installed daemon checks on 2026-11-12

Installed the verified Python wheel and restarted the daemon using the paths
from the installed hook. It reported a new running instance and `doctor` showed
zero warnings. The hook definition hashes matched across the restart. The
installed read API discovered a supported manifest with the same machine UUID
for each of the 15 configured projects. It opened all 15 event databases and
all 15 capture databases with matching versions.

The post-restart read found six fresh Codex hook events. There was no fresh
Claude hook event in that observation window.

A pre-deployment status check outside the sandbox reported `storage_unavailable`
for three project stores while the test suite was running. One diagnostic read
of `MAX(received_at)` returned `SQLITE_INTERRUPT` at the 100 ms health-query
limit. A fresh status check returned `running` before installation. WD-215 tracks
the transient finding.
