## Execution lifecycle boundary

`execution.normalize_events` already uses native execution identity to join a
yielded command and its `write_stdin` polls into one completed original command.
Running executions and unmatched native polls project as `waiting`.
`analysis.analyze` processes only `tool.finish` observations for repeat grouping,
so these native waiting observations do not count as repeated completions.
This is the existing [WD-164 behavior](wd164.md), not a new WD-161 exemption.

Subagent wait tools, sleeps, shell commands that check status, and opaque `exec`
scripts do not automatically establish the same native execution relationship.
JavaScript or shell text must not manufacture execution identity. For retained
tool finishes, the rule groups by agent, tool, input and outcome; adjacent calls
within a group stay linked when there is no recognized finished edit between
them **or** the captured output is unchanged. An edit plus changed output breaks
that chain. A review card's count of observed edit starts is not this finished,
agent-scoped rule counter.
