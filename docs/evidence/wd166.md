# WD-166: analysis backend selection and Codex isolation gate

Status: partial implementation, 2026-10-16. WD-166 remains open. Codex analysis is
unavailable; no authenticated model call has been made or advertised as verified.

## Offline installation inspection

The executable resolved in the development session reported
`codex-cli 0.163.0-alpha.10.2`. `codex exec --help` exposes `--ignore-user-config`,
`--ignore-rules`, `--ephemeral`, sandbox selection, schema output and JSON events.
That help does not establish a complete no-tools/no-context isolation contract.
`codex features list` exposes individual feature controls, which alone do not
prove absence of every built-in tool, instruction source or managed integration.
The implemented gate was also invoked against that installed executable with an
empty prompt and a preflight-only model label: it returned `isolation_unavailable`
in 141 ms, recorded the version and three informational flags, and launched no
model session. That timing is preflight latency, not analysis latency.

The [official configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference)
describes individual feature, instruction and integration controls. The
[non-interactive documentation](https://learn.chatgpt.com/docs/non-interactive-mode)
describes structured output and ephemeral execution. Neither inspected surface
established the complete isolation required here. This is a limitation of the
evidence collected, not a claim that every possible Codex isolation mechanism is
impossible. No prompt-based promise or read-only sandbox is accepted as proof.

## Implemented behavior

- `insights --backend claude|codex` and calibration `annotate` suggestions select
  analysis independently of the observed provider. Claude/`sonnet` stays the default;
  Codex requires an explicit model. Model and effort travel through `Request`.
- A fixed runner selector has no fallback. The Codex path constructs no model
  command and sends no evidence. It bounds version/help preflight by a shared
  deadline, refuses scratch directories inside registered projects, removes
  scratch state on exit/cancellation, and records version, requested selection,
  elapsed time and an unverified isolation reason.
- Missing executable and preflight timeout are reported explicitly. Nonzero or
  malformed version preflight cannot activate the backend. Missing usage, cost,
  context-window and output-limit values remain unavailable.
- Context-size memories separate analysis backends and retain legacy Claude
  reads. They do not implement or consume daemon call budgets.

## Remaining acceptance gates

Establish a version-scoped mechanism excluding project/user instructions, skills,
plugins, MCP, hooks, all tools and recursive Watchdog activity while retaining
authentication. Only then implement the authenticated bounded execution path,
strict result/schema/evidence handling, usage/model provenance, cancellation and
owned descendant-process cleanup, with provider-free behavioral tests. The
preflight tests above do not establish process-tree cleanup for a model session.

A separately authorized live isolated run must record version, isolation proof,
latency and available usage/cost before verification is claimed. WD-144/145/147
remain subject to their own reviews; no automatic judge, proposal or prefill is
enabled by this partial implementation. No live instance update is warranted:
this changes manual analysis selection, not observation or control.
