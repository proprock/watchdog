# WD-162: versioned materialized findings and session state

Completed 2026-10-16.

## Change and acceptance

Schema v9 stamps every `session_analysis` row with the producing report's
`rule_version`, including sessions with no findings. A missing or mismatched
version makes a settled session pending without another event. Existing v8 rows
retain an unknown version until refreshed; earlier migrations stamp the reports
they actually compute. Findings replacement remains transactional and uses the
existing quota admission, retry interval and per-tick budget.

Read-only `overview` counts only findings joined to an analysis row from the
installed rule version. Obsolete findings, gaps and timestamps are excluded while
the pending count exposes the work remaining. An unmigrated v8 store reports all
sessions pending without changing the database. Partial refreshes include only
the current sessions; after refresh, counts match merged per-session `report`
results, including fingerprint deduplication.

Provider-scoped reducer markers now cover both Codex and Claude. Changing
`state.VERSION` rebuilds states from retained events before tracker restoration;
the Codex-specific execution marker remains part of its version. Rebuilt states,
markers and analysis invalidation commit together after a space check. A failed
replay preserves the previous state and markers; unchanged versions skip replay.
The startup state rebuild remains separate from the budgeted findings queue.
Version-bump and migration rules are documented in [storage.md](../storage.md#schema-v9-versioned-recomputation-wd-162).
