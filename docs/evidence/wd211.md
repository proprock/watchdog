# WD-211 verification

Status: in progress. Full-suite and live-instance verification remain open.

A controlled test held the native adapter admission lock beyond its 100 ms wait. Before the fix, the adapter returned fail-open without storing the event and counted `invalid` rather than `busy`. The actual operation and OS error behind the earlier full-suite `io-error` reports are unknown; the controlled experiment reproduces the symptom but does not establish their cause.

The fix identifies contention only at `try_lock_exclusive` using the platform-specific `fs2` contention error, counts its admission timeout as `busy`, and leaves other I/O errors on their existing path. It releases the admission guard before writing quota and I/O counters after admission has been decided. The deterministic contention regression and two focused concurrent spool/quota tests passed. The bounded timeout can still reject an observation under contention; this change does not claim lossless delivery.

The complete native adapter test module passed 258 tests. `cargo fmt --check`, `cargo clippy --locked -- -D warnings`, and `cargo test --locked` passed (14 Rust tests).
