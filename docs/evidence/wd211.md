# WD-211 verification

Status: closed. The reproduced admission failures have deterministic
regressions, and the full suite and live update passed on Windows.

A controlled test held the native adapter admission lock beyond its 100 ms wait. Before the fix, the adapter returned fail-open without storing the event and counted `invalid` rather than `busy`. The actual operation and OS error behind the earlier full-suite `io-error` reports are unknown; the controlled experiment reproduces the symptom but does not establish their cause.

The fix identifies contention only at `try_lock_exclusive` using the platform-specific `fs2` contention error, counts its admission timeout as `busy`, and leaves other I/O errors on their existing path. It releases the admission guard before writing quota and I/O counters after admission has been decided. The deterministic contention regression and two focused concurrent spool/quota tests passed. The bounded timeout can still reject an observation under contention; this change does not claim lossless delivery.

The complete native adapter test module passed 258 tests. `cargo fmt --check`, `cargo clippy --locked -- -D warnings`, and `cargo test --locked` passed (14 Rust tests).

The `40593c8` red and `7339f07` green commits passed the TDD audit with the
named contention regression. A later full run recorded one `busy` loss in
the concurrent spool test. [WD-214](wd214.md) raised the native wait to
250 ms and verified that valid events survive brief contention.

## Windows lock initialization and I/O accounting

A deterministic Windows test locked byte zero of an empty admission file.
The previous adapter attempted to initialize the file before acquiring the
lock, counted one `invalid` loss, and saved no event. A separate Win32
`WriteFile` probe using a second handle confirmed error 33
(`ERROR_LOCK_VIOLATION`) for that write. A second regression put a directory
at the lock path and confirmed that a genuine open failure also counted
as `invalid`.

The adapter now acquires the lock before initializing the file. Contention
through the deadline counts as `busy`. Other admission-lock errors count as
`io` and leave an `admission-lock-io` fault without including paths or error
text. The retained [WD-184](wd184.md) `io-error` records contain no operation
or OS error code, so their exact historical cause remains unknown.
