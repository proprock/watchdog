## Focused investigation

The crash-status failure was reproduced from the saved test artifacts: the first heartbeat had been published, while clearing pending startup evidence was still in progress when the probe terminated the process. The test now waits for that cleanup before exercising a crash after successful startup. A separate deterministic health test covers the intermediate crash and confirms `degraded` with `startup_failed`; the focused crash and startup tests passed (4 cases).

A controlled Windows experiment confirmed that a reader holding the destination file for longer than the 100 ms retry window can produce WinError 5 in `atomic_write`; the process holding the file in the failed full-suite run is unknown. The two native concurrency tests passed in focused serial and parallel runs with temporary diagnostic instrumentation; their earlier `io-error` operation and cause remain unproven. Instrumentation was removed and the adapter rebuilt from the restored source.

Eight additional isolated runs of `test_concurrent_start_pause_and_explicit_resume` passed with temporary Windows handle-holder diagnostics enabled. The failure did not recur, so these runs did not identify the original holder. The instrumentation was removed.

The clean-clone full-suite results above precede the WD-211 native fix and the WD-213 test synchronization fix. Focused native tests passed after those changes; the full WD-184 acceptance suite has not been rerun from a clean clone on the new snapshot.

The subsequent full root suite in the working checkout, after those fixes, reported 2062 passed, 1 skipped and 1 failed. `test_native_concurrent_spool_commits_without_a_second_inbox_quota` stored seven of eight records. Its retained loss counters were busy 1 and quota, payload, invalid and io all 0: one invocation timed out waiting for admission. This confirms the failure path for this run, but the earlier io-error failures remain unproven. This was not a clean-clone acceptance run.
