## Delivered

- `pytest-xdist` and `pytest-timeout` in the dev group; `addopts` run `-n auto --timeout=180`
  (`-n 0` runs serially). The slowest test takes about 17 s.
- Session fixture `rust_adapter` in `tests/conftest.py`: `WATCHDOG_NATIVE_ADAPTER`, else
  `cargo build --release --locked` (a no-op when current), else skip, or fail when
  `WATCHDOG_REQUIRE_NATIVE=1` (set in CI). The 159 tests that use it carry the `native`
  marker. The two earlier copies of the fixture were removed.
- `tests/helpers/insights.py` (`store`, `invoke`, `runner_for`) replaced four copies of the
  `insights.run` option block, three CLI argv blocks, and the cross-module `store` import.
  The per-mode `_answer` builders build different schemas and were left as they are.
- CI: a `lint` job (fmt, clippy, ruff, ty) and a `test` job on the existing matrix (`cargo test`,
  pytest, `uv build`, CLI smoke), with `Swatinem/rust-cache` and `timeout-minutes`.
- Eleven Rust `#[test]`s in `native/src/main.rs` and `native/src/disk.rs`, plus one regression
  test for the macOS socket fix below (twelve in total).
- `DONE.md` is one line per task; its previous text is archived verbatim in
  [done-archive.md](done-archive.md).

## Measurements

Same Windows 11 host, 952 passed and 1 skipped both times: serial `-n 0` 174 s, parallel
`-n auto` 78 s. A first serial baseline (225 s) was discarded: two runs shared one `--basetemp`
and 9 fixture errors followed.

## First CI run: three defects found and fixed

The new jobs ran the suite on Linux and macOS for the first time since WD-139, which exposed:

- Two `tests/test_live_probe.py` tests assumed Windows paths (`Path(r"C:\...")` is one file name on
  POSIX; `commandWindows` is emitted only on Windows). The tests now follow the host.
- `ask_decision` in `native/src/main.rs` re-armed the read timeout after `shutdown(Write)`, which
  macOS rejects once the daemon has answered and closed. Every decision-channel answer was lost
  (25 failures, all fail-open silence). The timeout is now armed while the connection is open.

The macOS cause is an inference from the failure pattern; the confirmation is the green run.
