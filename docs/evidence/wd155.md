# WD-155: an adapter/daemon decision-schema mismatch is visible

## Why

The decision channel (WD-140) has a schema. An adapter that does not speak the schema the
daemon publishes in `policy/socket.json` fails open by design, so every rule that needs a
decision silently does nothing. On the user-local instance the installed adapter was a
0.1.4 build from 2026-09-30 that predates the channel: it has no `max_request_bytes`
handling, and both it and the newer local build reported the same version, so the version
alone could not tell them apart.

## What changed

- The adapter declares the schema it speaks in `--version`:
  `agent-watchdog-hook 0.1.5 (providers: codex, claude; decision schema 2)`. The adapter and
  package are 0.1.5; `native/Cargo.lock` and `uv.lock` were regenerated without `--locked`
  and committed.
- `readiness` has a `decision_channel` stage: `ready` when the adapter's schema equals the
  published one, `failed` (`decision_schema_mismatch`, with an action) when they differ,
  including an adapter that declares none, and `unknown` while no discovery file exists.
  It covers both directions, an old adapter with a new daemon and a new adapter with an
  old discovery file.
- `daemon status` adds `warnings: ["decision_channel_unused"]` when events a published
  subscription covers arrived after the daemon started and no adapter asked about any. The
  warning is evidence of silence and carries its window (`observed_since`). It does not
  appear for an idle daemon, with control switched off (no subscriptions), or for
  traffic no subscription covers.

## Verification

- Offline: five parametrized banner and schema cases and two end-to-end cases with the
  real adapter in `tests/test_readiness.py`; the counters, the warning and the
  switched-off case in `tests/test_daemon.py`; the Rust banner test in `native/`.
  `uv run pytest` 1240 passed, 1 skipped (before the last refinement; the touched modules
  were rerun). `cargo fmt --check`, `clippy -D warnings` and `cargo test` (13) pass.
- Live (2026-10-09), after the adapter was replaced (the old binary is kept beside it):
  `readiness claude` reported `decision_channel: ready` with adapter schema 2 and daemon
  schema 2, `ok: true`. The same function given the old adapter's banner against the live
  discovery file returned `failed` with `adapter_decision_schema: None`,
  `daemon_decision_schema: 2`. Control was switched off first
  (`[defaults] policy_intervene = false`), so the daemon publishes no subscriptions and no
  rule acts through the new adapter; turning it on is a config edit.

## Not covered

- The warning needs covered traffic, so it is silent while control is off. `readiness` is
  the check that works without traffic.
- Provider-side application of a delivered action is out of scope (WD-168).
