# WD-208 - Registry mutations keep every configuration section

Date: 2026-11-11.

## Change

`Registry._replace` rebuilt `Config` from four fields, so `rules`, `pricing` and
`pipeline_telemetry` fell back to defaults on `project add`, `remove`, `relocate` and
daemon auto-registration. It now builds the new configuration from every field of
`Config.model_fields` with only `projects` replaced and validates it through
`Config.model_validate`; the duplicate and overlap checks still run.

## Tests

- `tests/test_registry.py::test_registry_mutations_keep_every_configuration_section`
  covers `add`, `relocate`, `remove` and `resolve_or_auto_add`.
- `tests/test_daemon.py::test_auto_registration_keeps_rules_and_pricing_on_disk`
  covers the configuration file on disk after an auto-registration.
- Both failed before the fix and pass after it.
- `uv run pytest tests/test_registry.py tests/test_daemon.py tests/test_contracts.py`:
  145 passed. Full suite: 2049 passed, 1 skipped. `ruff check` and `ruff format --check`
  are clean for `src` and `tests`.

## Live instance

- Before: the live configuration held `[defaults]`, `[pricing]`, `[rules]`,
  `[rules.approved]` and 9 projects. Nothing had been lost yet.
- Backup `config.toml.bak-wd208` taken, wheel 0.1.5 reinstalled, daemon stopped and
  started at the same paths; `daemon status` reports `running`.
- After: the configuration file is byte-identical to the backup.
- The native adapter was not changed or replaced. A live auto-registration was not
  exercised; only the tests cover that path.
