# WD-225 historical Codex child receipt provenance

## Child callback coverage

Compared the 98 child rollouts from WD-223 with the read-only WD-195 snapshot.
Searched retained Codex hook envelopes by child session ID, agent ID, and the
child ID at the end of the transcript filename. Grouped the results by the
child's imported entry point.

| Imported entry point | Child rollouts | Children with a retained callback naming the rollout | Children with usage receipts |
| --- | ---: | ---: | ---: |
| `subagent:guardian` | 56 | 0 | 0 |
| `subagent:thread_spawn` | 38 | 38 | 38 |
| `vscode` | 4 | 4 | 4 |

All 33 parents with imported children have retained Codex callbacks. Sixteen
parents have both covered and uncovered children. The coverage split therefore
also occurs within individual parent sessions. The retained callback names for
covered children include `SubagentStart`, `SubagentStop`, and tool callbacks.
Both subagent events are in the legacy Codex hook event list that predates the
`PermissionRequest` addition tracked by WD-227.

Fifty-five guardian rollouts contain native usage records. None has a retained
child callback in the snapshot or an exact child ID match in the available
Watchdog log. Raw capture can find these rollouts by scanning provider history.
Usage enrichment registers a source in a project store when a retained hook
supplies an absolute transcript path. WD-223 replay verified that a supplied
source can be read. The historical evidence leaves provider emission and the
delivery stage unresolved. WD-230 tracks a versioned live probe of that boundary.

## Two project stores for one child

Exactly one covered child had callbacks naming its rollout in two stores.
Both sets named the same absolute transcript path and parent session. Their
checkout IDs match the two distinct registered roots.

| Project | Callbacks naming the child rollout | Distinct native usage responses |
| --- | --- | ---: |
| A | 68 `PreToolUse`, 67 `PostToolUse`, 1 `SubagentStart` | 80 |
| B | 6 `PreToolUse`, 4 `PostToolUse` | 80 |

The callback windows overlap on November 11, 2026. Both stores still have one
matching `transcript_sources` row under the parent session with a positive
reader offset. The 160 receipt rows share 80 event IDs and 80 native response
IDs, with identical usage per response as verified in WD-223. The parent and
child rollout metadata name a working directory under project A, which also
supplied the raw capture stream to Insights.

The adapter forwards each callback's working directory. The daemon resolves
that directory through the registry, and each store registers the transcript
path from its own callback. Enrichment reads the source within each store, so
both stores can derive the same response from the full rollout. Insights
preserves each store's project provenance when it imports those facts. The
evidence supports retaining project-scoped accounting. A rollout-level total
would need a separately defined scope before combining records across projects.

Verification used the WD-195 snapshot, the WD-223 per-child report, retained
hook envelopes, the Watchdog log, and read-only queries of the two source
registrations. No live provider call was made. The investigation changed only
ticket records and this evidence.
